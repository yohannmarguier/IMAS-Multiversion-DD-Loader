# The read path holds no intermediate value

`al_read_data` takes `void **data`. IMAS-Core allocates the buffer and the HLI frees it, and no seam in the mirrored ABI frees memory. The shim therefore receives no caller buffer on a read, and it cannot overflow one. A read applies its value transformations to the buffer IMAS-Core returned, and the shim materialises no intermediate value between conversion steps.

A `merged` rule reads its left DD paths in precedence order and stops at the first hit. A read that finds no data returns success with a null data pointer, so a miss allocates nothing and the shim frees nothing. Precedence names the DD spelling that is current, not the value that is correct: when two left paths both hold data and disagree, no conversion rule repairs the written data, and reading every candidate yields knowledge of the disagreement but never a better value. The shim returns the precedence-first value. Detecting the disagreement is a reporting concern, and it is the only decision that would make a read hold two buffers at once. ADR 0012 settles it as a deliberate refusal to detect: the aliases are never compared, the read holds one buffer, and the path is logged as potentially lossy and unverified.

A rule whose retype changes the rank of a DD path fails at the seam, before the shim calls IMAS-Core. The single such rule in the equilibrium 3.39.0 ⇄ 4.1.1 artifact is `grids_ggd/grid/space/coordinates_type`, which the DD changes from `INT_1D` to `STRUCT_ARRAY` at 4.0.0, and which is the only data-type change in that IDS between those versions. An HLI does not read a `STRUCT_ARRAY`; it opens an arraystruct context on it. Serving that rule requires the shim to create a context record for a context ID that IMAS-Core never issued and to answer reads from its own memory, which makes the shim a data store for one subtree instead of a converter. This refusal is deliberate and remains part of the design: a later effort that reopens it must accept the fabricated context record, not discover the constraint again.

The shim resolves a conversion chain to one value transformation before it changes any data. A unit redefinition refuses, a refusal can arise at a late step, and a refusal must not find the buffer already changed; folding first also identifies a net identity, such as a COCOS change of 11 to 17 to 11, and then skips the pass. The initial artifact has one step, so the fold composes nothing today and the statement constrains the future conversion-map generator, whose chronological history and merge design belong to a separate effort. Whether the single pass runs in place on IMAS-Core's buffer or on a copy is not decided here; that decision belongs with the value-transformation ADR, which inherits the guarantee that a refusal leaves the buffer untouched.
